# Sanic-Admin v0.4.1 发布说明

**发布日期：2026-10-27。**

---

## 这一版做了什么

三项质量收口，每一项都由一次具体的、可复现的故障驱动：

| 项 | 之前 | 现在 |
|---|---|---|
| **时区** | 时间字段输出空格分隔，前端与后端各自猜时区 | 统一的 UTC aware 契约，ISO 8601 输出，AMIS 显式声明 utc |
| **AMIS** | 3.4.0，E2E 门禁只能验证部分路径 | 6.13.0，SDK 体积从 45MB 降到 27MB |
| **MCP 提案** | `discard_proposal` 只按前缀判断，可误删他人分支 | 归属标记 + SHA 校验，只删自己建的 |

## Breaking — 时间字段改为标准 ISO 8601

API 输出的时间字段此前是 **空格分隔**：

```
"created_at": "2026-10-24 12:55:31+00:00"
```

现在是 **`T` 分隔**的标准形式：

```
"created_at": "2026-10-24T12:55:31+00:00"
```

**客户端如果按空格切分解析会失败。** 请改用 `datetime.fromisoformat()`
（Python 3.11+ 两者都能解析）或等价的 ISO 8601 解析器。

涉及 11 个模型/资源文件、21 处序列化点。变更的根因是模型层用 `str(datetime)`
而非 `.isoformat()`：前者产出非标准形式，Python 3.10 及更早的 `fromisoformat`
会直接拒绝。

### 时区契约（新）

完整约定见 [docs/timezone.md](../timezone.md)：

- **存储**：所有 `DatetimeField` 以 UTC aware 保存。
- **输出**：带偏移的 ISO 8601，例如 `2026-12-01T02:00:00+00:00`。
- **输入**：接受带偏移的值（换算为 UTC）与不带偏移的值（**按 UTC 解释**）。
- 进程 `TZ` 环境变量不影响上述任何一条。

`Tortoise.init` 与 aerich 配置显式声明 `use_tz=True, timezone="UTC"`。此前依赖
Tortoise 默认值（实测默认行为恰好相同），这是把隐含依赖变成显式契约。

### AMIS 前端的时区语义

AMIS `input-datetime` 默认把用户看到的**本地时间原样提交**，而服务端按契约
当作 UTC——上海用户输入 `10:00`，库里存 `10:00Z`，实际差 8 小时。服务端修不了
（它拿不到时区），必须在控件上声明。

生成器已给控件加 `utc: true`（提交前本地→UTC、回显时 UTC→本地），
`valueFormat` 改为 `YYYY-MM-DDTHH:mm:ssZ`。列表列的 datetime 同样处理。

实测（TZ=Asia/Shanghai 真实浏览器）：

```
库里原值      : 2026-12-01T02:00:00+00:00
编辑弹窗显示  : 2026-12-01 10:00:00        （02:00 UTC + 8h ✓）

选本地 10-07 00:00 → 请求体 "onboarded_at": "2026-10-06T16:00:00+00:00"
                                              （00:00 UTC+8 = 16:00 UTC ✓）
```

## AMIS 3.4.0 → 6.13.0

四个 SDK 静态文件（`sdk.js` / `rest.js` / `sdk.css` / `helper.css`）从 npm 官方包
`amis@6.13.0` 提取，与本仓文件逐字节比对 sha256 一致。

**`rest.js` 必须与 `sdk.js` 同批替换**——两者版本耦合，单独替换会让 SDK 内部
模块解析失败。

**体积 45MB → 27MB（-40%）**：删除 10 个从未被加载的主题文件
（`ang`/`antd`/`cxd`/`dark` 各自带 `-ie11` 变体、`sdk-ie11.css`、`ie11-patch.css`）。
确认方式是「先把 HTML 注释剔除再搜文件名」——`sdk-ie11.css` 只出现在
`index.html` 的一行注释里，不剔除会误判成有引用。

`thirds/`（11MB）**保留**：`sdk.js` 会动态加载其中的 `monaco-editor` 与 `hls.js`，
删除会让对应组件 404。

**已知限制**：仅验证当前使用的主题（`sdk.css` / `cxd` 系列）。若要切换到
ang/antd/dark，需从 npm 包补回对应 CSS。IE11 支持随这些文件一并移除。

## MCP 提案的归属校验

`discard_proposal` 原来只校验 `proposal/` 前缀就允许删除。问题是**任何人手工建一个
`proposal/xxx` 分支都会被本工具删掉**，而删除不可逆。

改为三条同时满足才允许删：

1. 分支名是 `proposal/` 前缀
2. 存在归属标记 `refs/specgen/proposals/<name>`（本工具独占命名空间）
3. 标记指向的 SHA 等于分支当前 SHA（证明没被人改过）

标记在提案分支 fetch 回用户仓库**之后**才写——分支确实落地了才登记，
避免留下指向空气的标记。

**临时目录残留清理**：`make_proposal` 的 `finally` 在进程被 kill 时不会执行，
目录会累积。新增启动时清理（仅 `--allow-write` 模式），五条安全约束全部是
「宁可漏删，不可误删」：只扫 tempdir 一层、名字匹配 `sanic-specgen-*`、
**必须**有 `.sanic-specgen-workspace` 标记文件、mtime 超 24 小时、
标记里的 pid 非当前进程且已不存活。**绝不按通配删除。**

## 工程质量

### 测试纪律

本版新增 [AGENTS.md](../../AGENTS.md) §3.6 「断言必须做破坏实验」，记录了一天之内
抓出的 8 个假测试。核心结论：

> 测试全绿不代表测试有效。一条从不失败的断言和没有断言是等价的，但前者更危险。

配套三条判据：破坏后至少一个观察点要变；测试没红时先排查「断言测不到」还是
「破坏没破到」；报告破坏实验必须贴原始输出行，不能只写「红 ✓」。

### 修掉的一处测试死锁

`test_pre_push_hook_blocks_even_with_remote` 曾偶发挂起 600 秒并泄漏孤儿进程。
根因是两个叠加：`git push` 往 pre-push 的 stdin 写 ref 列表而 hook 不读；以及
`subprocess.run(timeout=)` 超时只杀直接子进程，孙进程（`git-receive-pack` 与 hook）
变成孤儿。修法是 `Popen(start_new_session=True)` + `os.killpg` 整组杀，
并把 stdin 读空。全套 MCP 测试从 31 秒降到 14 秒，零孤儿。

### CI 新增真方言时区验证

`migrations-dialects` job 里新增一步，在**真实的 MySQL 8 与 PostgreSQL 16** 上
验证时区契约（naive 按 UTC / `+08:00` 换算 / `Z` 后缀 / 跨时区一致）。
SQLite 上 Tortoise 会自己归一，本地绿不代表 MySQL 也对——MySQL 的 `DATETIME`
本身不带时区，全靠 ORM 在写入前转好。

## 已知限制

- **`use_tz` 的负向验证未取得结论。** 原计划在 CI 的 `migrations-dialects` job 上
  把 `use_tz` 改为 `False` 跑一次，验证「去掉该配置后 MySQL 的时区断言会失败」。
  实测 **GitHub 未对该临时分支触发任何 workflow**（`check-runs total=0`，
  `gh run list --branch tmp/tz-negative` 全程为空；即使把 draft PR 改成 ready
  也没有），因此**未取得 MySQL / PostgreSQL 上的原始结论**（非阻塞）。

  已关闭该临时 PR 并删除分支（它含故意破坏，不能留在可合并状态）。
  这条限制的影响面：`use_tz=True` 在 SQLite 上的行为与 `False` 相同（Tortoise 0.20
  的归一逻辑与它无关），所以本机测试无法区分二者；该配置的价值体现在**将来升级
  ORM 或换方言时防止行为漂移**，而非当前的可观测差异。

- **AMIS 仅验证当前主题**（`sdk.css` / `cxd` 系列）。切换到 ang/antd/dark 需从
  npm 包补回对应 CSS。
- **MCP 提案归属标记只证明「分支由本工具创建且未被改动」**，不证明内容经过审核。
- **临时目录清理只覆盖本工具自己的产物**（`sanic-specgen-*` 前缀 + 标记文件），
  用户手工 `git worktree` 留下的目录不在范围内。

## 升级须知

- **没有数据迁移。** 存量值本来就是 UTC aware（Tortoise 0.20 的行为），
  格式变化只发生在输出层。
- **客户端需检查时间解析**：按空格切分的解析器要改成 ISO 8601。
- **AMIS 页面需重新生成**：`python -m tools.specgen generate`，否则已有的
  `input-datetime` 控件不会带上 `utc: true`。
- `APP_VERSION` 为 `0.4.1`。
