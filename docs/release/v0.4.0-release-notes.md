# Sanic-Admin v0.4.0 发布说明

**发布日期：2026-10-24。**

---

## 这一版做了什么

**规格即代码**。把「加一个业务模块」从「写模型 + 写路由 + 写页面 + 写迁移 + 写测试」
变成「写一份 YAML，然后跑两条命令」。

```bash
# 1. 写 specs/ticket.yaml
# 2. 生成
python -m tools.specgen generate
python -m tools.specgen migrate
```

产出的 14 个文件全部由生成器拥有：模型、CRUD API、权限点、AMIS 列表页与表单、
测试、三方言迁移。人只需要审 diff、开 PR。

演示（含真实命令、输出与耗时）：
[docs/demo/ai-module-in-10-minutes.md](../demo/ai-module-in-10-minutes.md)

### 为什么不是「又一次脚手架」

生成是**确定性**的：同样的规格总产出逐字节相同的结果，所以规格变更可以被 diff
审查，而不是对比两次运行后的数据库状态。这是让 AI 参与开发的前提——模型的输出
必须能逐字核对。

## Breaking changes

### 1. production 环境缺 aerich 账本会**拒绝启动**

v0.4 起 production 不再跑 `generate_schemas`，改为检查 `aerich` 账本表是否存在，
缺失即拒绝启动。

**从 v0.3.x 升级必须走四步**（详见 [docs/migrations.md](../migrations.md) §2b）：

```bash
# 0) 备份（SQLite 复制库文件；MySQL/PG 逻辑备份或快照）——不可跳过
# 1) 补列 + 置位管理员（v0.3.2 已发布的手写脚本）
DATABASE_URL="<生产库 DSN>" python scripts/migrate_v0_3_2_must_change_password.py
# 2) 按方言选基线 → 校验结构一致 → 写入账本
python scripts/migrations/select_dialect_baseline.py --auto
DATABASE_URL="<生产库 DSN>" python scripts/migrations/baseline_existing_db.py \
    --url "<生产库 DSN>" migrations/models
# 3) 应用迁移（此时应为 no-op，只校验账本对齐）
DATABASE_URL="<生产库 DSN>" python scripts/migrations/upgrade.py
# 4) 启动应用
```

**顺序不可颠倒**：基线化只写账本、不改表结构。跳过第 1 步直接基线化会以 rc=3
被拒绝（脚本会比对库结构与模型并点名缺失的列）；即便绕过，账本会宣称已对齐而库里
实际缺列，`aerich upgrade` 永远不会补，运行期才报错。

#### 给 v0.3.4 用户

**即使你已经升到 v0.3.4，同样要走完这四步。** v0.3.4 的表结构虽然较新，但
`scripts/migrations/` 整个目录是 v0.4.0 才有的，v0.3.4 的库里没有 aerich 账本，
production 启动仍会被拒绝。

第 1 步的补列脚本 `migrate_v0_3_2_must_change_password.py` 是**幂等**的——
若库里已有 `must_change_password` 列，会跳过建列，只做管理员置位逻辑。
所以在 v0.3.4 的库上运行它是安全的。

### 2. 鉴权加固（来自 v0.3.4）

若你从 **v0.3.3 及更早**升级，还有两处 breaking（**v0.3.4 用户不受影响**）：

- **改密成功后不再保留当前会话**：一并作废并轮换签发新会话（响应新增
  `token_rotated: true`）。自管 token 的客户端必须改用响应下发的 `Authorization`，
  否则下一次请求 401。
- **初始口令要求强度**：`INITIAL_ADMIN_PASSWORD` 少于两类字符时，production 启动即
  `ConfigError`。

详见 [v0.3.4 发布说明](v0.3.4-release-notes.md)。

## 新增

### 三方言迁移链（#10）

aerich 0.7.2，基线按方言各存一份：

```
migrations/dialects/{sqlite,mysql,postgres}/0_*_init.py
migrations/models/          # aerich 工作目录，装当前部署方言
```

`select_dialect_baseline.py` 切方言时会**连同增量一起装**——只换基线不够，
增量里的类型也分方言（MySQL `DATETIME(6)` vs PG `TIMESTAMPTZ`）。

`upgrade.py` 在升级前对**每个**迁移文件做 md5 比对，装错方言返回退出码 4。

### `specgen migrate`（#17）

为结构变化产出三方言增量迁移，**离线渲染，不需要数据库驱动**。

| 变更 | 行为 |
|---|---|
| 新表 / 新列（可空，或 NOT NULL 带 DEFAULT） | 自动生成 |
| 删列 / 删表 / 改类型 / 改默认值 | **拒绝**，要求手写 |
| 给已有列加 UNIQUE | **拒绝** |
| 新列带 UNIQUE / 外键 | **拒绝**（需单独 `ADD CONSTRAINT`） |
| 新列 NOT NULL 且无 DEFAULT | **拒绝**（已有行无值可填） |

拒绝的理由统一：这些变更的**数据迁移语义**无法从模型推断，猜错会在生产丢数据。

### MCP 只读层（#15）

`tools/mcp_server`，stdio 传输，五个工具：

| 工具 | 作用 |
|---|---|
| `list_resources` | 列出 `specs/` 下资源与字段摘要 |
| `describe_resource(name)` | 规格全文 + 生成物路径 + 权限点 |
| `validate_spec(yaml_text)` | pydantic 校验，错误带字段路径 |
| `preview_generate(yaml_text)` | 临时目录生成，返回 unified diff |
| `check` | 等价 `python -m tools.specgen check` |

**全程不写仓库**：preview 前对仓库相关文件取哈希快照，返回前复核；改动即抛错。
资源名白名单 + 拒绝路径分隔符/`..`/绝对路径 + `relative_to` 二次校验。

配置方法见 [docs/mcp.md](../mcp.md)。

### MCP 写入路径（原型，默认关闭）

只读层负责「看和校验」，写入层负责「出提案」——但**不负责合并**。

```
propose_spec_change(resource, yaml_text, base_ref="master")
    → 隔离 clone 里写规格 → commit → fetch 回用户仓库的 proposal/<branch>
list_proposals()
    → 列出提案分支与 commit
discard_proposal(branch)
    → 删掉提案分支
```

**这三个工具默认不注册**，必须用 `--allow-write` 启动才出现在 `tools/list` 里。
理由：MCP 是 stdio 本地进程，没有账户体系；默认暴露写能力等于「谁能拉起进程谁就能写」。

### 「AI 不能 push 或合并」是机制保证，不是约定

四层，逐层收口：

| 层 | 做法 |
|---|---|
| **一、clone 里没有推送目标** | 不带 remote；另把 clone 的 `.git/config` 直接改成 `push.default=nothing`、`credential.helper` 置空——不给凭据可用 |
| **二、即使有人加了 remote，pre-push hook 也无条件拦截** | hook 里 `exit 1`；且 `core.hooksPath` 显式指向 clone 自己的 hooks，防止用户全局 `hooksPath` 让我们的 hook 失效 |
| **三、工具代码的 git 命令白名单** | 子命令级 + **参数级**——`clone --upload-pack=<cmd>` 这类「子命令合法但参数能执行任意程序」的写法被挡住 |
| **四、合并能力根本不存在** | **刻意不实现 `apply_proposal`**。把提案写回主工作区等于绕开「人来合并」；应用应由人执行 `git merge` / `git cherry-pick` |

另有两项隔离措施（不是独立层，而是贯穿各层的运行前提）：`GIT_CONFIG_GLOBAL=/dev/null`
与 `GIT_CONFIG_NOSYSTEM=1`，确保不读用户/系统的 git 配置。

### 原型的已知限制

| 限制 | 说明 |
|---|---|
| `discard_proposal` 只看 `proposal/` 前缀 | 不校验分支是否由本工具创建。前缀目前足够区分，但不够强 |
| 24h 残留清理是 TODO | 靠 `finally: shutil.rmtree()`；进程被 kill 时临时 clone 会残留。自动回收可能删掉人正在看的东西，故留到下一轮 |
| 仅本地 stdio，无账户级权限 | `--allow-write` 是**进程级**开关，不是账户级 RBAC |
| `describe_proposal` 未实现 | 查看单个提案的完整 diff 需人工 `git show` |
| 生成器与迁移未接线 | 最小原型只做「写规格 → 提交 → fetch」；生成与迁移走已有的 `preview_generate` 路径，接线留到下一轮 |
| 审计写 stderr，不写数据库 | MCP 侧不强制依赖运行中的服务；审计内容不含规格全文 |

机制的完整论证见 [docs/mcp-write-path.md](../mcp-write-path.md) §6「AI 不能 push 或合并」；
已实现与未实现的逐项清单见同文件 §9。

**测试**：本次新增 58 项（`test_mcp_write_path.py` + `test_mcp_write_registration.py`，
含参数化展开）；MCP 相关测试合计 108 项（另 50 项来自 #15 的只读层）。

### CI 增加方言 DDL 实跑（#14）

`migrations-dialects` job 在 GitHub runner 上用 `services` 起 MySQL 8 与 PostgreSQL 16，
每种方言跑两条路径（新库跑完整链 / 存量库只跑增量），再用 `information_schema`
断言列类型、唯一约束、外键与 `ON DELETE` 规则。

**为什么必须有**：`check_migrations` 只把 DDL 当**文本**比对，从不执行。MySQL 的
DDL 与 SQLite 差别很大，语法错误在只跑 SQLite 的 CI 里一路绿灯。这一版就抓到过一次：
MySQL 基线的 `\'` 被 Python 还原成裸引号，任何全新部署都在第一步报 1064。

## 修复

### MySQL 基线注释引号未转义（#17，高危）

`migrations/dialects/mysql/0_*_init.py` 里写的 `\'` 在 Python 三引号字符串中会被还原
成裸 `'`，实际发出的 SQL 变成：

```sql
COMMENT '令牌类型，如 'activation', 'password_reset', 'two_factor''
```

引号提前闭合 → MySQL 报 1064。**任何在 MySQL 上全新部署 v0.4 的尝试都会在基线第一步
失败**，而当时 CI 全绿。现已修为 `\\'`，并补静态守卫测试。

### date/datetime 字段在 AMIS 表单里缺 `type`（#21）

`render_amis._control()` 漏了 date/datetime 分支，生成出没有 `type` 的控件，
AMIS 报「找不到对应的渲染器」，**整个新增/编辑弹窗无法提交**。`customer.birthday`
同样中招。

**这个缺陷只有真跑浏览器才能发现**：API 测试、单元测试、CI 全绿，坏的是页面 JSON。
现在 `_control()` 末尾有兜底 `raise`——新增类型却忘了映射时生成阶段直接炸。

### 其它

- `specgen migrate` 曾因渲染路径引入 `aiomysql` 而在 CI 上直接失败（#17）
- 切方言只换基线、不换增量（#17）
- `check_migrations` 的方言基线比对口径不一致（#11）

## 已知限制

| 限制 | 说明 |
|---|---|
| **MCP 写入路径是原型** | `discard_proposal` 只按 `proposal/` 前缀判定，不校验是否由本工具创建；24h 临时目录残留清理是 TODO（进程被 kill 时会残留）；仅本地 stdio，`--allow-write` 是**进程级**开关而非账户级 RBAC；`describe_proposal` 未实现，查看单提案完整 diff 需人工 `git show` |
| **`spec:write` 权限点未实现** | 目前只有 `--allow-write` 这个进程级开关，没有账户级鉴权 |
| **软删除的唯一约束仍占位** | 删了再建同值会冲突（409）；需要复用同值的场景可加时间戳后缀 |
| **`datetime` 不带时区** | 存库为带时区值；客户端提交裸时间按服务端时区解释，跨时区请用 ISO 8601 带偏移 |
| **AMIS 仍是 3.4.0** | 6.x 升级评估在 v0.4 之后 |
| **生成器只处理新增** | 删列/改类型等结构性破坏变更需手写迁移 |
| **`IF NOT EXISTS` 静默跳过** | 目标库已有同名但结构不同的表时，增量会跳过而不报错。部署前请跑 `check_migrations` 自查 |
