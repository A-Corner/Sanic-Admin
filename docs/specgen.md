# specgen：规格即代码

规格 YAML（`specs/*.yaml`）是**唯一事实源**。确定性生成器据此产出：

| 产物 | 位置 |
|---|---|
| Tortoise 模型 | `app/generated/models/<resource>.py` |
| CRUD API（复用 `@requires_permission`、`validate_fields`、`register_view`） | `app/generated/resources/<resource>.py` |
| RBAC 权限点 | `app/generated/permissions.py`（导入时并入 `ALL_PERMISSIONS`） |
| AMIS 列表/表单页 + 菜单 | `amis/pages/<resource>-list.json`、`amis/pages/site.json`（带 `x-specgen` 标记的菜单项） |
| 契约测试 | `tests/generated/test_gen_<resource>.py` |

所有生成文件带 `generated by specgen — do not edit` 标记（JSON 用 `_generated` 键，site.json 用 `x-specgen` 菜单项标记）。**不得手改**。规格中**不得出现 AMIS 语法**（`extra=forbid`，出现即报错）；AMIS 只是 `tools/specgen/render_amis.py` 这一个可替换的渲染层。

## 命令

```bash
python -m tools.specgen validate   # 只校验规格，报「文件: 字段路径: 原因」
python -m tools.specgen generate   # 生成/更新所有产物；清理已删除规格留下的带标记陈旧文件
python -m tools.specgen check      # 只检查漂移（CI 用），有差异退出码 1
```

同一份规格两次生成逐字节相同（输出按资源名排序，无时间戳；文件头只含规格路径与内容哈希）。

## 规格格式

```yaml
resource: order            # 小写标识符；不得与内置资源 account/role/... 重名；文件名必须同名
table: orders              # 默认 = resource
plural: orders             # URL 复数，默认 resource + "s" -> /api/v1/orders
label: 订单
fields:
  - name: title
    type: string           # string | text | int | float | bool
    max_length: 128        # 仅 string，默认 255
    required: true         # 与 default 互斥
    unique: true           # 模型 unique + API 409
    format: email          # 仅 string
    choices: [a, b]        # string/int；与 default、format 的组合会被校验
    default: a             # 必须在 choices 内、类型匹配
    list: true             # 出现在 AMIS 列表
    searchable: true       # 参与 ?keyword= 搜索
belongs_to:                # 外键（RESTRICT）；API 字段名为 <name>_id
  - {name: customer, target: customer, required: true, list: true}
permissions: {actions: [read, create, update, delete]}   # 权限点 order:read ...
menu: {icon: fa-receipt, order: 70}
```

属性贯通：`default/choices/required/max_length/unique` 同时进入模型、API 校验（框架 `validate_fields`：先 `extract_whitelisted` 再校验提取结果）、AMIS 表单（select / maxLength / required / value）、生成测试。`belongs_to` 创建/更新时校验被引用记录存在（400），删除被引用的父记录返回 409。

## 自动注册（不再手工接线）

只在两个文件里各有一行**一次性**接线（已提交，之后新增资源不再改）：`app/models/__init__.py` 导入 `app.generated.models`；`app/api/resources/__init__.py` 导入 `app.generated.resources`（导入即注册路由与权限点）。菜单由生成器改写 `site.json`；测试路径替换由 `tests/conftest.py` 通用正则处理。

### 全权限角色判定

`role.py::_role_grants_all_permissions` 判定「全权限角色」时只比较**核心资源**（注册表去掉生成资源）。否则新增一份规格就会让存量全权限角色失去受保护管理员身份。内置 admin 角色仍同步为注册表全量权限（含生成资源）。

## AI 使用约定

1. **只改 `specs/`**，不手改任何生成文件；
2. 运行 `python -m tools.specgen generate`，再按改动范围跑 `tests/generated`、`tests/test_specgen.py`、`tests/test_authorization.py`；
3. 提 PR：规格改动 + 生成物在同一提交序列；CI 跑 `python -m tools.specgen check`，漂移即失败。

## 迁移

改规格后的固定流程：

```bash
python -m tools.specgen generate    # 重写生成物（模型/API/页面/测试）
python -m tools.specgen migrate     # 为结构变化产出三方言迁移
python scripts/check_migrations.py  # 守门：迁移链与模型必须一致
```

`specgen migrate` 一次产出三方言**同名**迁移：

```
migrations/models/1_<ts>_specgen.py            # 当前部署方言（默认 SQLite）
migrations/dialects/{sqlite,mysql,postgres}/1_<ts>_specgen.py
```

三份必须同名：aerich 以文件名作账本版本键，切方言后账本里记的名字要能在目录里
找到同名文件，否则会被当成「没跑过」而重复建表。

### 能自动迁移的

| 变更 | 行为 |
|---|---|
| 新表 | `CREATE TABLE` |
| 新列（可空，或 NOT NULL 带 DEFAULT） | `ALTER TABLE ... ADD` |

### 不能自动迁移的（会报错，要求手写）

生成器对下列变更**拒绝生成**并退出码 1。理由都是「数据迁移语义无法从模型推断」，
猜错会在生产丢数据或让迁移中途失败：

| 变更 | 为什么拒绝 |
|---|---|
| 删列 / 删表 | 数据会永久丢失，需人确认 |
| 改类型 | 隐式转换可能截断（`VARCHAR(16)` → `VARCHAR(8)`）或失败 |
| 改默认值 | 影响新行语义，旧行是否回填需人决定 |
| 给已有列加 UNIQUE | 现有数据可能已有重复，要先清洗 |
| 新列带 UNIQUE / 外键 | `ALTER TABLE ADD COLUMN` 的行内 `UNIQUE` 在 PG/SQLite 不受支持，外键同理，需单独 `ADD CONSTRAINT` |
| 新列 NOT NULL 且无 DEFAULT | 已有行无值可填，ALTER 会因非空约束失败 |

### 三方言渲染不需要数据库驱动

`migrate` 直接读模型元数据渲染三方言 DDL，**不连库、不需要装 aiomysql / asyncpg**。
渲染与连接是解耦的：只有真正 `upgrade` 时才需要驱动。

（实现上要绕过 tortoise 的包级 import——`tortoise.backends.mysql.__init__` 会
`import aiomysql`，所以按文件路径直接加载 `schema_generator.py`。见
`tools/specgen/migrations.py` 的 `_load_generator_class`。）

### 局限

- **只处理新增**。上表列出的变更一律拒绝，需人工编写迁移。
- **多方言文件名可能分叉**：如果某次变更只在一种方言下被判定为「需要迁移」
  （例如不同方言对同一列的规范化结果不同），三份文件名可能对不上。发生时会由
  `check_migrations.check_dialect_baselines` 报出来——部署前务必跑它。
- **`IF NOT EXISTS` 的静默跳过**：增量用 `CREATE TABLE IF NOT EXISTS`，若目标库
  已有同名但结构不同的表，会被跳过而不报错。部署前请跑 `check_migrations` 自查。

### 切方言部署

```bash
python scripts/migrations/select_dialect_baseline.py mysql   # 装基线 + 全部增量
DATABASE_URL="..." python scripts/migrations/upgrade.py      # 应用（含方言校验）
```

`select_dialect_baseline.py` 会连同**增量**一起装（只换基线不够——增量里的类型也
分方言：MySQL `DATETIME(6)` vs PG `TIMESTAMPTZ`）。`upgrade.py` 在升级前对**每个**
迁移文件做 md5 比对，装错方言返回退出码 4。

## 外键（belongs_to）与权限

生成的资源在创建与更新时校验外键，**先判权限、再判存在性**：

- 调用者必须对引用目标持有 `<target>:read`，否则一律 **403 `FORBIDDEN`**。
  这样 400（目标不存在）与 201（目标存在）的差异不会泄露某个 id 是否存在，
  防止通过外键字段枚举目标表。
- **外键值未变时同样要求该权限**（安全默认值）：即使 PUT 只是改别的字段、
  外键原值原样回传，也按"引用该目标"处理。若某类调用方不需要读目标表，
  应改为不传外键字段而不是依赖"值没变就跳过"。
- 外键字段缺省（不传）时不触发该校验。

## 字段类型

`string` / `text` / `int` / `float` / `bool` / **`date`** / **`datetime`**。

`date` 生成 `DateField`，`datetime` 生成 `DatetimeField`；API 校验用 `Date()` 规则
（接受 `YYYY-MM-DD` 或 ISO 8601 文本），AMIS 表单用 `input-date` / `input-datetime`。
注意 `datetime` 回显会带时区后缀（Tortoise 归一化为 UTC），客户端按解析后的时刻比较即可。

## 列表排序（sorting）

```yaml
sorting:
  default: -id              # 不带 ?ordering= 时的默认排序
  allowed: [id, name, status]   # 白名单；未列入的字段传 ?ordering= 一律 400
```

`allowed` 留空表示**不接受任何** `?ordering=` 参数（传了就 400）——默认最小暴露面。

## 软删除（soft_delete）

```yaml
soft_delete: true
```

开启后 `DELETE` 只把 `deleted` 置真（保留数据与审计痕迹），列表与详情默认过滤已删除行。
关闭（默认）时 `DELETE` 走物理删除。

**已知取舍：软删除的行仍占用 `unique` 约束。** 删除后重建同值记录会返回 **409**
（`unique` 是表级约束，不看 `deleted`）。当前选择保留这一行为而非改成「部分唯一索引」，
理由：

- 部分唯一索引（`WHERE deleted = false`）在 SQLite 上需手写索引、MySQL 不支持表达式索引，
  三方言的一致性成本高于收益；
- 保留约束能防止「删了又建」造成的重复历史行堆积，审计链路更清晰；
- 需要"删除后复用同值"的场景，可给该字段加时间戳后缀，或由业务侧改用非唯一字段。

若后续确有强需求，可在 v0.4 引入 `partial_unique` 规格开关并配套迁移。

## CI 集成

```bash
python -m tools.specgen check   # 生成物与 specs/ 不一致时退出码 1，CI 变红
```

CI 的 test job 已接入该步骤：改了规格却没重新生成、或手改了生成物，构建会直接失败。
正向对照已实测（篡改一个生成文件 → 退出码 1；恢复 → 0）。
